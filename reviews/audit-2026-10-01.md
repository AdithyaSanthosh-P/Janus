# Kernel and voice-path audit (1 Oct 2026)

A read-only audit of the kernel, the voice bridge and the LiveKit worker, against 72 voice recordings of the current code (judged) and the source. Nothing was changed by the audit itself; each finding was reproduced before any fix. This page keeps the findings and what became of them. Status is as of 4 Oct 2026.

## Headline

The kernel was not the main source of failures; the voice bridge was. One bridge bug closed the user's turn while they were still speaking, which turned 52 of 72 recordings into two or more turns. Recordings that stayed one turn passed about as often as text replay (13 of 17); two turns passed 8 of 24 and three or more 6 of 31. The kernel's correction machinery (read-set cancellation, split-turn merge, chunk-anchored cancellation) had not fired once on real voice, because the corrections arrived after the calls had gone out.

## Design-level findings

| # | Finding | Status |
|---|---|---|
| A1 | The kernel could not hear that the user was speaking: its only floor signals were text chunks and an end-of-turn derived from a timer, and a late hosted transcript re-armed that timer mid-speech (44 of 102 and 35 of 92 end-of-turns fired during speech). | **Fixed.** End-of-turn follows VAD silence, waits for outstanding transcripts, and the kernel receives a `user_speech` signal (`Config.vad_floor_enabled`). On 26 recordings re-run: 0 early closes (31 before), 16 passes (12 before). A second cause, a fixed 4 s give-up on a slow transcript, was fixed on 3 Oct: a turn now stays open while a transcription is running. |
| A2 | "Reads are free to speculate" does not hold on a benchmark that scores every executed call: an extra read fails the recording. | Mitigated by A1 and `settle_reads_enabled`; the design asymmetry remains. |
| A3 | The full-duplex machinery (prefix speculation, chunk anchors, the TRIAGE hold) assumes streaming input, but speech-to-text is non-streaming, so each segment is transcribed in isolation. | **Open.** Streaming transcription is the named next step. |
| A4 | Latency is a serial chain of fixed waits and blocking model calls (about 5.7 s to the first call, 7.2 s to the first audio on single-turn recordings). | Open; first word is 8.5 s on the 3 Oct run. Part of it is deliberate (1.5 s turn-end wait, settle window). |
| A5 | DECIDE is a single pass in fixed order, so work one component unlocks for an earlier one waits for the next step (the clarify-wake liveness bug was one instance). | Instances fixed; the class is not closed. |
| A6 | Failures were invisible: step exceptions were swallowed and the decision log held no proposals or gate rejections. | **Fixed.** Exceptions are logged and written to the decision log; each record carries gate rejections, dispatches and per-event detail. |
| A7 | The interpreter prompt contradicted itself (`_2`-suffixed names both required and forbidden). | **Fixed.** |
| A8 | Reproducibility: unpinned dependencies, hosted model IDs, and the Docker path never run end to end. | Dependencies pinned and a source digest recorded; every measured run used the native path, and `./reproduce.sh` with a GPU has not been run end to end. |

## Kernel and wiring bugs (each with a runnable reproduction)

| Bug | Status |
|---|---|
| End-of-turn armed by a late transcript while the user speaks (R01) | Fixed (A1). |
| Restating a written value ("$1500" → "1500") counted as a change: needless cancel, a false "already went through", the plan dropped (R04) | Fixed: equivalent restatements are not changes (`canonical.equivalent_values`). |
| A follow-up could not reference a finished task's results ("add one of them to the cart") (R08) | Fixed: the interpreter sees each finished action's compacted result. |
| Independent actions ran strictly in sequence, so a clarifying sibling blocked a fully specified one (R09) | Fixed: `Config.parallel_independent_actions`. |
| The incomplete-turn check missed a trailing "…" and "under/about" (R02) | Fixed. |
| The duplicate check ignored schema defaults the adapter fills in later (R03) | Fixed: the fingerprint includes defaults; an honest "already done" finish. |
| The same ACK spoken after every re-plan (R06b) | Fixed. |
| A call sent with an empty required argument | Fixed: blank required arguments are rejected. |
| `min_speech_gap_ms` defined but not enforced | Left as is: the transport plays queued utterances in order. |

Verified correct, no bug: a correction during interpretation or the settle window yields exactly one call; the async driver releases held calls with no further events; kernel step time is under 0.4 ms over 200 turns.
